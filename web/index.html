정상 통신과 실패를 비교하세요.

공격 실험에서는 별도 Eve 프로세스가 TCP 패킷을 변경합니다. 거부 결과는 수신 프로세스의 실제 검증 오류에 근거합니다.

작은 수 모드는 개인 지수를 쉽게 추측할 수 있습니다. Eve의 임의 키 복호화 실패는 작은 DH 자체의 안전성을 뜻하지 않습니다.
프로토콜을 읽는 방법

작은 수에서 시작하는 암호 통신.

작은 수 모드로 공개값과 공유 비밀을 계산한 뒤, 큰 수 모드와 패킷 변조 실험을 비교해 보세요. 두 공개값 교환 다음에는 키 확인과 응용 메시지 단계가 이어집니다.

01

공개값을 보내도, 개인 지수는 보내지 않습니다.

A = gᵃ mod p, B = gᵇ mod p를 계산합니다. 네트워크에는 AES-GCM으로 보호된 A와 B가 이동하며 a와 b는 각 프로세스 안에 남습니다.

Bᵃ mod p = Aᵇ mod p = gᵃᵇ mod p
02

사전 공유키와 세션키는 다릅니다.

K_AB는 공개값의 암호화·인증에 사용합니다. 새로운 DH 공유 비밀 S는 HKDF의 입력이고, 세션 루트 키에서 역할별 키 확인 키와 방향별 응용 키를 따로 유도합니다.

K_AB → 공개값 보호 / S → HKDF → 새 키들
03

암호화만큼 인증이 중요합니다.

AES-GCM은 암호문과 AAD의 무결성을 검증합니다. header의 송신자·유형·버전·세션·그룹·순번·양측 난수도 인증합니다. 인증 실패 시 계산과 통신을 중단합니다.

04

키를 만들었다면 서로 확인합니다.

두 DH 패킷만으로 동일 키 보유가 명시적으로 확인되지는 않습니다. 양측 난수, 공개값, DH 패킷 transcript를 KDF에 결합하고 역할별 HMAC-SHA-256을 상호 검증합니다.

05

재전송 방어에는 상태가 필요합니다.

Bob은 인증된 세션 ID를 SQLite에 영속 저장합니다. 재전송 실험은 정상 실행을 먼저 완료하고 Bob을 재기동한 다음 같은 DB에 이전 패킷을 주입합니다. DB 삭제·교체·서버 간 비공유 시 이 중복 ID 검사는 유지되지 않습니다.

06

교육용 설계의 경계를 기억하세요.

표준 EKE·PAKE 또는 검증된 상용 인증 키 교환을 구현한 것이 아닙니다. K_AB를 알아내면 기록된 공개값을 복호화할 수 있지만, 큰 수 DH 개인 지수나 과거 S가 자동으로 복구되지는 않습니다. 능동 위장 공격에는 노출됩니다.

공식 근거: RFC 3526 그룹 14 · 공개값 부분군 검증 · HKDF
